## 1. 采纳落点摘要

### 1.1 提权模型 → ADR-035（新增）

主进程永不提权；提权操作走窄域 helper（`runas` 自身实例 + 固定动词集 + 结构化参数）；
一次提权只做一件事；执行前重校验（TOCTOU）；UAC 拒绝是正常输入；
提权边界不得随功能蔓延（新增第三类提权操作必须先修订 ADR-035）。

### 1.2 防火墙一键 → ADR-025 增补 1~8

规则模板（绑 exe + `LocalSubnet4` + 双端口独立规则 + `Profile Any`）、
启动健康检查 + Repair（原地更新、读回校验、不得变宽）、不自动弹 UAC、
标准用户文案、TOCTOU、GPO 不对抗、不依赖首听弹窗、撤销入口。

### 1.3 临时地址 → ADR-026 增补 1~7

Advanced 定位、禁硬编码、冲突预检（含局限说明）、子网重叠预检、UAC 事务不合并、
生命周期（持续到显式撤销）、receipt 式撤销、驳回「只加不改」机制。

### 1.4 诊断与文案 → ADR-024 增补 1~5

零提权、三就绪拆分、文案禁令与六前提、可达性 ≠ 允许被控、发现前分类。

### 1.5 十条失败模式

见 §0-Q5 表，已逐条映射到 ADR-035 / ADR-025 / ADR-026 的具体条目。

### 1.6 生命周期语义（评审点名的漏问项）

| 状态 | 性质 | 生命周期 | UI 表达（M9/M10 要求） |
| --- | --- | --- | --- |
| 身份（deviceId / 密钥 / 证书） | 一次性（per-user，DPAPI） | 永久（除非用户显式重置） | 首启静默建立；设置页可见设备码/指纹/重置 |
| 防火墙规则 | 一次性 + 健康检查 | 持久，直到显式「移除访问」或 exe 路径变化（→ Repair） | 缺失/失效时提示；健康时不出现 |
| 网络诊断 | 每次运行 | 一次性呈现 | 健康时零摩擦（不占版面） |
| 临时私有地址 | **显式高级操作** | **持续到用户显式撤销**（不随退出清理、不自动清理） | 常驻徽章「已添加测试用地址 <addr>（移除）」 |
| 设备发现 | 每次运行 | 自动持续 | 主界面，与「本机就绪」视觉分离 |

## 2. 本机实测（Windows 行为断言 → 证据）

> 全部在 A 机（Win11 25H2 / build 26200，管理员会话）以真实防火墙规则完成；
> 测试规则使用独立前缀并在实验后立即删除（`remaining matches = 0` 两轮均确认）。
> 原始输出曾留在 `%TEMP%\lr-fw-probe*.txt`，结论以下表为准。

| # | 断言（来自评审或由评审引出） | 实测结论 | 证据 |
| --- | --- | --- | --- |
| W1 | 便携目录移动 → 绑路径规则「静默失效」 | **实锤**：目录改名后规则**完全不报错、不变化**（`Enabled=True`、`Program` 仍指旧路径、`PathExists=False`、scope 不变）——它会一直挂在那里但永远匹配不到任何进程 | 实验 B：建规则 `-Program ...\dirA\fake-app.exe` → 读回 `Enabled=True/PathExists=True` → `dirA` 改名 `dirB` → 读回 `Program` 仍是 dirA 路径、`PathExists=False` |
| W1b | （普查）「程序更新/移除 ⇒ 规则悬挂」是否真实存在 | **真实存在**：本机 596 条规则中，375 条绑路径的 filter 里 **18 条是孤儿**（路径已不存在）。例子：`msedgewebview2.exe` 两个旧版本目录（版本升级后悬挂，与便携目录移动同构）、`p2phost.exe`×4、`ehome\*.exe`×6 | `Get-NetFirewallApplicationFilter` 全量 + `[Environment]::ExpandEnvironmentVariables` 后 `Test-Path`（**首轮误报 265 条是因为没展开 `%SystemRoot%`——检测代码本身必须先展开变量**） |
| W2 | `LocalSubnet4` scope 可写可读可校验 | **成立**：`New-NetFirewallRule -RemoteAddress LocalSubnet4` 被接受，读回原样字符串 `LocalSubnet4` | 实验 B：`CREATE: scope accepted = LocalSubnet4`；`RemoteAddress='LocalSubnet4'` |
| W3 | （基线）现行 lab 规则与产品模板的差距 | 现行两条规则是**宽规则**：`Profile=Any`、`RemoteAddress=Any`、`Program=Any`——「任意程序、任意来源、打到端口就放行」。验收物料够用；**产品模板绝不能照抄**（增补 1 的收窄点全部有据） | `Get-NetFirewallRule -DisplayName 'LanRemote*'` 全字段读回 |
| W4 | GPO 覆盖行为 | **本机不可验证**：596 条规则 **0 条** GroupPolicy 来源（个人机无域策略）。域环境行为标注**未测**，产品按「不对抗、如实报告」实现 | `PolicyStoreSourceType` 全量统计 |
| W5 | 地址冲突预检（ping 探测的可行性） | **可用但有明确局限**：未使用地址 100% 丢包、本机地址 0 ms 响应 → 能发现「会应答的占用者」；**不能证明空闲**（静默主机、屏蔽 ICMP 都会漏报）→ 必须叠加用户确认 + 添加后校验 | `ping -n 1 -w 1000` 两个地址对照 |

| W7 | UAC 拒绝的行为（`ERROR_CANCELLED` 路径） | **未测**：需要用户点一次「否」，不与本轮其他实验混做；列入遗留（§6）。**不据此下结论** | —（本机提权路径本身已两次实测：`ShellExecuteExW(lpVerb="runas")` + `WaitForSingleObject`，EXIT=0） |

## 3. 驳回 / 改写

### 3.1 「追加地址只加不改」——机制驳回（意图采纳）

评审要求：追加地址必须「只加不改」——不换 DHCP / 网关 / DNS / metric / profile。

**驳回理由（本机两次实测支持，ADR-026 §3 已记录）**：Windows 上**不存在**「保留 DHCP 的同时
追加一个静态地址」的路径——`New-NetIPAddress` 与 `netsh interface ipv4 add address` 都会把接口
`Dhcp` 置为 `Disabled` 并丢弃租约。也就是说：**「追加」这个动作本身就必然连带一次 DHCP→静态转换**，
这不是实现选择，是平台机理。评审的理想形态（零连带变更）在 Windows 上不可达。

**接受其意图并已落地**：把变更面压到最小并**精确记账**——
① 追加地址不设网关（不抢默认路由）、不改 DNS；
② 状态文件记录「为追加而一并记录的原参数」与「自己加的那一个地址」，撤销 = 恢复这两类（receipt 式）；
③ 文案必须**如实**说明「该网卡将从 DHCP 变为静态（已回填全部原参数），移除时恢复」——
不许把有代价的操作描述成无感；
④ 幂等撤销 + 自校验三条（ADR-026 现行 §3）。

（metric 的具体行为属于 M10 验证项，现在不下断言。）

### 3.2 不依赖 Windows 首次监听弹窗（形态 (a)）

无需实测即可驳回**作为依赖**：该弹窗是否出现、何时出现受用户环境与设置控制（可被关闭），
且它只能覆盖「程序监听」这一个环节、与「显式 + UAC」的既有原则不合。
我们不需要它：形态 (b)（App 内一键 + 窄域规则）在 W1/W2/W6 实测支撑下已可自足。
**注意：这不是断言「弹窗不可靠」的 Windows 事实**，而是「不作为机制依赖」的设计决定。

### 3.3 评审之外、由实测新发现的两点（一并记录）

1. **`set-lab-ip.ps1 -Undo` 不还原网络类别**：脚本只设置 `NetworkCategory Private`（第 221 行），
   `-Undo` 路径与函数内都没有还原动作。影响极低（类别不影响 IP 连通性与本工具规则），
   但严格说违反「可逆」。**M3 物料冻结，不修**；记录于 §6 遗留，M3 收尾后另行处理。
2. **孤儿检测代码必须先展开环境变量**（W1b 首轮误报 265 条）：产品健康检查读回
   `Program` 字段时同样适用——比对前必须先 `ExpandEnvironmentVariables`。
