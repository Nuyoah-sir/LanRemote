## 本机环境实测（修正：我第一版读错了）

- 实测 `Win32_OperatingSystem.Caption` = **Microsoft Windows 11 专业版**，Version 10.0.26200，Build 26200，
  DisplayVersion 25H2 → 本机是 **Windows 11 25H2**，不是 Windows 10。
- **陷阱**：`HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProductName` 在 Windows 11 上仍是
  `Windows 10 Pro`。我第一版只读了这个值就写下「Windows 10 Pro 25H2 / build 26200」——**这个组合不成立**。
  判系统版本必须用 `Win32_OperatingSystem.Caption`，不能用这个注册表值。
  （这是外部模型纠正我的，我用 CIM 复测确认它对。）

## 红队评审回来后的分流（产出 `docs/M3_REVIEW_TRIAGE.md`）

评审 27 条，按三桶处理。**我没有直接采信它标 [VERIFIED KNOWLEDGE] 的 .NET 默认值，全部本机实测了一遍**
（临时 console 项目在 %TEMP%，反射打印 `SslXxxAuthenticationOptions` 默认值 + JSON 经验测试）：

- `AllowDuplicateProperties` 默认 **True** 且**后者覆盖前者** → 证实，且比评审说的"歧义"更严重
- `AllowTlsResume` **两端默认都是 True**（评审只点了客户端）；`EnabledSslProtocols` 默认 `None` → 评审漏了这条
- `MaxDepth` 属性值默认 **0**（内置上限 64），评审写成"默认 64"需修正
- 我第一版经验测试因属性名大小写不匹配得出假结论（看着像"没拒绝"），改对 `[JsonPropertyName]` 后才测准
  → **经验测试本身也要自检**

新增两条 ADR：
- **ADR-027** 发现层身份冲突不得静默 last-write-wins（M3 不改 M2；最晚 M4 落地冲突标记 + 禁用连接；
  同 deviceId+同指纹+不同 IP 是多网卡良性广播，不得误杀）
- **ADR-028** M3→M4 契约：上下文必须不可变携带 `{deviceId, endpoint, expectedPin, presentedPin}`，
  **M4 transcript 必须绑定 presentedPin**（只绑 expectedPin 会留下凭据中继缺口）——这条是评审最有价值的发现，
  我原以为规格的 "modified cert fingerprint fail" 已覆盖，其实那是篡改场景，不等价
