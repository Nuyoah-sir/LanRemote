## 本环境的几个坑（下次别再踩）

1. **PowerShell 工具在本机会话里不回显输出**（返回空），`powershell.exe` 从 Bash 调用会被安全策略拦截
   → 需要 Windows 侧操作时，优先找「不需要 PowerShell」的替代路径（例如用 Python 解压 zip）。
2. **`reg.exe` 被安全黑名单拦截**，不要尝试用它查注册表，也不要绕道。
3. **`.NET 10` 的 `dotnet new sln` 默认生成 `.slnx`**，规格要求 `.sln` 时必须加 `-f sln`。
4. Git Bash 里给 PATH 追加路径要写成 `/c/Users/...`，写 `C:\...` 不生效。
5. **后台程序用 `(cmd &)` 会被回收**：做「启动两个进程」这类验证时，第二个进程看不到第一个，
   会得到假的失败结论；必须在同一条命令里用 `$!` 拿 PID 并 `kill -0` 确认存活。
6. App 项目里有 3 个文件必须显式 `using System.IO;`（XAML 编译路径下隐式 usings 少了 IO），
   Core 项目不需要。删掉会编译失败。

## M1.3 ECDSA Certificate KeyUsage Fix（同日，M1 最后一次修改）

ECDSA P-256 end-entity 证书此前声明 `DigitalSignature | KeyEncipherment`。
RFC 5480 对 `id-ecPublicKey` 的 end-entity 证书只允许 digitalSignature / nonRepudiation /
keyAgreement；keyEncipherment 是 RSA 密钥传输语义，在 EC 证书里声明属 profile 违规。
改为 `new X509KeyUsageExtension(X509KeyUsageFlags.DigitalSignature, critical: true)`。
serverAuth EKU 保留；P-256 / SHA-256 / EphemeralKeySet / 指纹算法 / PFX+DPAPI / 5 年 / CA=false 全未动。

新增 3 条测试：KeyUsage 恰好等于 DigitalSignature、组合 profile（P-256+CA=false+KU+EKU+id-ecPublicKey）、
重载后 KeyUsage 不变。test **200 passed / 0 failed**。Last code commit `9e75fce`。

**本机开发 identity 已手工重置**（备份到 `backups/secrets.bin.pre-m1.3-reset.bak`）：

## set-lab-ip v1 断网事故 → v2 重写（17:06–17:25）

用户按 v1 跑 `-Role A` 成功、`check-env.ps1` PRE-CHECK PASSED，然后 `-Undo`
→ **电脑 A 以太网失去全部可用 IPv4**（只剩 APIPA 169.254.194.126，无网关无 DNS）；
第二次 `-Undo` 抛 `No IPv4 adapter found`。
已手工恢复：`Remove-NetIPAddress` + `Set-NetIPInterface -Dhcp Enabled` + `ipconfig /renew`
→ 复核 `172.100.166.220/24`、Dhcp=Enabled、网关 172.100.166.254、DNS 172.100.162.101/102。

**根因（实测，不是推测）—— Windows IPv4 不支持「DHCP 地址 + 附加静态地址」共存：**

| 操作 | 预期 | 实测 |
| --- | --- | --- |
| `New-NetIPAddress` 在 DHCP 接口上追加 | 共存 | 接口 `Dhcp` → `Disabled`，租约丢失 |
| `netsh interface ipv4 add address` | 共存 | 同上 |
| 追加后再删除该地址 | 复原 | 只剩 APIPA，无网关/DNS |

## 第三个脚本缺陷：虚拟网卡被误选（B 机现场暴露）

B 机跑 `-Role B` 时脚本选了 **VMware Network Adapter VMnet1**（192.168.11.1），
把 `192.168.1.20` 加到了虚拟网卡上 → A 机 0 条 192.168.1.20 日志，完全收不到。

**原因**：VMware/VirtualBox/Hyper-V/TAP/托管网络网卡同样是 `Status=Up`、
`MediaType=802.3`、且带 IPv4 地址，所以「第一个 Up 的 802.3 且有非 APIPA 地址」
这个启发式会选中它们；但它们的流量**不上物理网线**。

**修复（commit 5e9f245）**：
- `Test-VirtualAdapter`：按 InterfaceDescription/Name 关键字排除
  （VMware/VMnet/VirtualBox/Hyper-V/TAP-Windows/OpenVPN/WireGuard/Npcap/Bluetooth/
  WAN Miniport/Wi-Fi Direct/Hosted Network/Loopback/Teredo/ISATAP/RAS Async/
  ZeroTier/Sangfor/PANGP/Fortinet/AnyConnect/Tunnel/Virtual 等）+ `本地连接*`
- 真实网卡里优先「802.3 + 有默认网关」的那张
- 打印网卡描述；若仍疑似虚拟网卡则醒目告警并提示 `-InterfaceAlias`

**B 机补救**：`-Undo -InterfaceAlias "VMware Network Adapter VMnet1"` →
`-Role B -InterfaceAlias "以太网"`（172.100.166.65）→ 重启 LanRemote。

**教训：机器上装了 VMware/VirtualBox/Docker/VPN 时，任何"自动挑网卡"都必须显式排除虚拟网卡。**
