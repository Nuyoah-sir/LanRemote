## 本环境的几个坑（下次别再踩）

1. **PowerShell 工具在本机会话里不回显输出**（返回空），`powershell.exe` 从 Bash 调用会被安全策略拦截
   → 需要 Windows 侧操作时，优先找「不需要 PowerShell」的替代路径（例如用 Python 解压 zip）。
2. **`reg.exe` 被安全黑名单拦截**，不要尝试用它查注册表，也不要绕道。
3. **`.NET 10` 的 `dotnet new sln` 默认生成 `.slnx`**，规格要求 `.sln` 时必须加 `-f sln`。
4. Git Bash 里给 PATH 追加路径要写成 `/c/Users/...`，写 `C:\...` 不生效。
5. **后台程序用 `(cmd &)` 会被回收**：做「启动两个进程」这类验证时，第二个进程看不到第一个，
   会得到假的失败结论；必须在同一条命令里用 `$!` 拿 PID 并 `kill -0` 确认存活。
6. App 项目里有 3 个文件必须显式 `using System.IO;`（XAML 编译路径下隐式 usings 少了 IO），
   Core 项目不需要。删掉会编译失败。

## M1 设备身份与安全存储（同日完成）

产出：`CrockfordBase32`（Core.Encoding，解码会拒绝尾部填充位非 0 的非规范写法）、
`DeviceCode`（`Base32(SHA256(deviceGuid)[..5])` → `XXXX-XXXX`）、
`SecretFile`（`LRSC` + version + length + DPAPI payload）、`DataProtection`、`SecretGenerator`、
`DpapiSecretVault`（唯一读写入口 + 原子写 + 锁）、`DpapiAccessSecretStore`（实现 `IAccessSecretStore`）、
`DeviceCertificateService`（ECDSA P-256 自签名、PFX 存 secrets.bin、PersistKeySet 重载）、
`DeviceIdentityService`；App 侧接入真实身份 + 密钥显示/复制/重新生成 + 剪贴板 30 秒条件自清。

验证（真实执行）：
- build PASS，0 警告 0 错误；test **175 passed / 0 failed**（M0 87 → +88）
- 真实数据目录两次冷启动：设备码 `QPKE-2CPC`、证书指纹前缀 `3A3D791A` 完全一致
- secrets.bin 1807 字节，magic/version 正确，全文无 `accessKey`/`deviceGuid`/`certificatePfx` 明文
- 日志扫描：长度 ≥20 的 token 全是路径/类名，无 Base32 形态串

**踩过的坑（下次别再踩）**：

1. **`ProtectedData` 必须显式 NuGet 引用**，即便 TFM 是 `net10.0-windows`。
2. **`ProtectedData.Protect` 参数名是 `optionalEntropy`**，不是 `entropy`。
3. **`X509CertificateLoader.LoadPkcs12` 只有 3 个参数**（没有 `loaderOptions`）；
   `new X509Certificate2(bytes, pwd, flags)` 已过时（SYSLIB0057）。
4. **`X509Certificate2.NotBefore/NotAfter` 返回本地时间**，与 `DateTime.UtcNow` 直接比较
   在 UTC+8 会误判 —— 已有一个测试因此失败，改成 `.ToUniversalTime()`。
5. **8 个 Base32 字符 = 5 字节**（不是 1 字节），写断言时注意长度换算。
6. **模拟「重启」必须新建 `DpapiSecretVault` 实例**，只换 store 不生效（vault 有缓存）。

新增 ADR：014（deviceGuid 与证书一并进 DPAPI bundle）、015（PFX 随机口令，不提供额外机密性）、
016（PersistKeySet|Exportable 为 M3 TLS 可用性）、017（设备码算法固定）。
